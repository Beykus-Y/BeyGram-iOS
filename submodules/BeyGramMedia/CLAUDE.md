# BeyGramMedia

BG Mix (AutoMix) and BG Beat for iOS. Notes for work in this directory:

- `BGMediaCore/` is a git submodule of `Beykus-Y/BG-Media` (pure C++20 core). Do not edit it here; change the core in BG-Media and bump the pin. The pin follows BG-Media `dev` (the commit the Android app builds), not `main`; bump it together with the source list in `BUILD`.
- Initialise it before building: `git submodule update --init submodules/BeyGramMedia/BGMediaCore`.
- `Sources/BGMediaMixPreparation.*` is the platform-neutral track pipeline (same steps as BG-Media's desktop `prepareMixTrack` on dev). Decoding is injected: the decoder must refuse before allocating past `maxDecodedBytes` and call the checkpoint between chunks. Limits and the reserve-and-interleave helper live in `Sources/BGMediaPcmLimits.hpp` (host test: `Tests/BGMediaPcmLimitsTests.cpp`).
- `Sources/BGMixPlayer.mm` decodes with AVAudioFile and plays through AVAudioSourceNode on AVAudioEngine. `MixSession::update()` runs from a CADisplayLink on the main thread in the foreground and from a 0.1 s timer in the background, where the display link does not fire. The render block must never capture self or allocate. `+[BGMixPlayer sharedPlayer]` is the app's one player. Interruptions, route changes and engine restarts are handled in the same file. The lifecycle and driver rules are in `docs/bg-mix-player-api.md`, section «Жизненный цикл».
- The public player surface (track and snapshot types, observers, seek) is the contract in `docs/bg-mix-player-api.md`. `Sources/BGMediaMixState.hpp` maps the MixSession snapshot to the published state and holds the driver and interruption decisions (host test: `Tests/BGMediaMixStateTests.cpp`).
- The pinned core and the platform-neutral pipeline were compiled and run on Linux (g++ 13, `-std=c++20`). The Objective-C++ files and the Bazel target have not been built: they need macOS with Bazel.
- `Sources/BGMixViewController.mm` is a minimal BG Mix screen (queue, play, next, clear, in a bottom toolbar). It observes the shared player while it is on screen and never stops it: closing the screen does not stop the mix. `BGMixFeatureEnabled()` reads `beygram.feature.musicLibrary` from UserDefaults (the key BeyGramKit writes; off by default). The entry is the BG Music settings page (`submodules/BeyGramMusicUI`), shown in the Settings advanced list and pushed through `BeyGramHostedViewController`.
- `Sources/BGWaveViewController.mm` is the BG Wave invite screen. It only checks pasted `bg://wave/v1/` links (shape and length). It does not join sessions: host audio capture and the WebRTC stack are not built for iOS (issue #50). Gated by `beygram.feature.bgMedia`.
- `BGWaveCore/` is the transport-independent BG Wave session layer, in portable C++20 with no ObjC or UIKit. `BGWaveInvite` decodes and encodes invites in both forms (`bg://wave/v1/` and the https wrapper, as Android's `BgWaveLink.kt`), and refuses a link over 4096 characters before decoding. A non-positive time means the wall clock. `BGWaveSession` runs a Host or Listener over `bgmedia::wave::WaveAudioPipeline` with an injected codec and transport. Production will inject Opus and a P2P transport in later stages; tests use `Pcm16WaveCodec` and `SimulatedWaveTransport`. It needs the BG-Media core at the dev pin (`src/wave/*`), the same commit as Android. Host test: `./build-input/bazel-9.2.0-darwin-arm64 test //submodules/BeyGramMedia/BGWaveCore:BGWaveCoreTests --test_output=all`. Stages and what is verified: `docs/bg-wave-ios.md`.
- `third-party/libdatachannel/` is the vendored BG Wave P2P transport: libdatachannel v0.22.5, the version Android builds, with BoringSSL and WebRTC's libsrtp (no second copy). It compiles with `-Drtc=bgrtc`, so consumers write `rtc::` and get `bgrtc::`. Never call `rtc::Cleanup()` in the app: it shuts the shared libsrtp down under WebRTC. Pins, licences and checks: `third-party/libdatachannel/README.md`.
- The Swift adapter that makes BG Mix the engine of the `.music` playlist is `submodules/TelegramUI/Sources/SharedMediaBGMix.swift`, with its hooks in `SharedMediaPlayer.swift`. While the music path is on, MediaManager owns the lock screen, the remote commands and the audio session, so BG Mix code never registers `MPRemoteCommandCenter` or `MPNowPlayingInfoCenter` handlers. BG Mix runs AutoMix and the playlist follows it. Rules: `docs/bg-mix-player-api.md`, section "MediaManager (музыкальный путь)".
